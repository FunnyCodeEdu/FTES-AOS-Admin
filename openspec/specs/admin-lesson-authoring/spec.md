# admin-lesson-authoring Specification

## Purpose
Soạn bài học trong admin console: màn bài học MỘT trang (không tab), danh sách bài có mô tả sửa
tại chỗ, kéo-thả đổi thứ tự, popup tạo bài theo loại (video / slide / tài liệu) gắn luôn nội dung,
và xem video ngay từ danh sách.
## Requirements
### Requirement: Lesson editing is a single page

`LessonEditPage` SHALL render lesson authoring as one page without tabs: lesson info (title +
description, saved via `PATCH /api/v1/courses/lessons/{id}`), video (player + file upload + an
input accepting an upload-service video id or a YouTube link), markdown content (existing editor
with AI assistance), and attached slides/documents. The former "Xem trước", "Học thử" and
"Bài tập" tabs SHALL NOT be rendered on this page.

#### Scenario: Editing title and description

- **WHEN** a manager changes the title and description and presses "Lưu"
- **THEN** a single PATCH SHALL be sent and the course tree query SHALL be invalidated so the
  lesson list shows the new values

#### Scenario: Read-only viewer

- **WHEN** the caller cannot manage the course
- **THEN** every input and upload control on the page SHALL be disabled

### Requirement: Lesson list shows and edits descriptions

The lesson list SHALL show each lesson's description under its title, editable inline for
managers. Saving the tree SHALL send `description` only for lessons whose description actually
changed, and SHALL include the description when creating a lesson.

#### Scenario: Description persisted

- **WHEN** a manager types a description for a lesson and presses "Lưu thay đổi"
- **THEN** `PATCH /courses/lessons/{id}` SHALL carry `description`, and the value SHALL survive a
  page reload

### Requirement: Lessons reorder by drag and drop

Lesson rows SHALL be draggable within their section; dropping a row onto another row of the same
section SHALL move it before (dragging upward) or after (dragging downward) the target in the
draft tree. Reordering across sections by drag SHALL be ignored. The existing up/down buttons
SHALL keep working, and the new order SHALL reach the backend only when "Lưu thay đổi" is pressed.

#### Scenario: Drag a lesson up

- **WHEN** the third lesson of a section is dragged onto the first
- **THEN** it SHALL become the first lesson in the draft and the tab SHALL show the unsaved marker

### Requirement: New lessons are created from a popup

"Thêm bài học" SHALL open a modal asking for lesson type (VIDEO / SLIDE / DOCUMENT), name and
description, plus type-specific content: a video id or YouTube link, a slide file, or markdown
generated by the AI document modal. Submitting SHALL create the lesson through the backend and
then attach the provided content, invalidating the course tree. The popup SHALL refuse to open
while the draft tree has unsaved changes (the refetch would discard them) or when the section has
not been saved yet.

#### Scenario: Create a video lesson from a YouTube link

- **WHEN** a manager submits the popup with type VIDEO, a name, and a YouTube link
- **THEN** the lesson SHALL be created, the link SHALL be attached as its video source, and the
  lesson SHALL appear in the list without pressing "Lưu thay đổi"

#### Scenario: Unsaved draft blocks the popup

- **WHEN** the draft tree is dirty and the manager presses "Thêm bài học"
- **THEN** a warning SHALL ask them to save first and the popup SHALL NOT open

### Requirement: Viewing a lesson plays its video

The "Xem nội dung" drawer SHALL embed the lesson video player above the content; lessons without a
playable video SHALL simply omit the player instead of showing an error.

#### Scenario: Video lesson previewed from the list

- **WHEN** a manager opens the drawer for a lesson whose video is READY
- **THEN** the player SHALL render and play the lesson stream
